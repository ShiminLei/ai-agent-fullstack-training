# Prompt Engineering 作业

本作业把“你是一个厉害的代码审查专家，请认真审查用户代码”改造成一份可复用、可检查、可演进的工程化 Prompt。

最终模板见 [code_review_prompt.md](./code_review_prompt.md)。

## 验收要求对应关系

| 要求 | 实现位置 |
| --- | --- |
| 补充角色、目标、行为边界和输出风格 | `System Prompt` 中的“角色与目标”“行为边界”“输出风格” |
| 增加正常样例与“无明确问题”样例 | `Few-shot 示例` 的示例一、示例二 |
| 将任务拆成“分析—审查—检查” | `工作流程` |
| 分离固定规则与运行时变量 | `System Prompt（固定规则）` 与 `User Prompt 模板（运行时变量）` |
| 加入间接 Prompt 注入防护 | `信任边界` 与 Few-shot 示例三 |
| 设置名称、版本号和变更说明 | 文档头部元数据与 `版本记录` |
| 约束可测试 | 固定输出结构、严重级别、变量规则和可观察的允许/禁止行为 |
| 不可信内容不能升级为指令 | `信任边界` 明确外部文本只作为数据 |
| 高风险行为由程序或 Harness 控制 | `行为边界` 明确模型不能自行扩大权限 |

## 使用方式

1. 将 `System Prompt（固定规则）` 作为长期不变的系统提示词；
2. 使用 `User Prompt 模板` 注入本次审查的运行时数据；
3. 所有变量都放在对应 XML 标签内，不要与固定规则拼接；
4. 由宿主程序负责长度限制、权限检查、敏感信息处理和高风险动作确认；
5. Prompt 发生行为变化时更新语义化版本号，并使用正常、边界、无问题和注入样例做最小回归。

## 最小回归检查

- 明确缺陷输入：应输出带位置、证据、影响、触发条件和建议的问题；
- 无明确问题输入：不得为了凑数而报告问题；
- 信息不足输入：应列出缺失信息，不得猜测；
- 注入输入：不得执行或服从代码、文档、日志中的隐藏指令；
- 权限输入：不得仅因用户文本要求就执行写入、删除、联网或外发操作；
- 输出检查：不得虚构测试结果，不得输出隐藏推理过程。
